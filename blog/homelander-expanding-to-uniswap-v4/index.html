Homelander Is Expanding to Uniswap v4

Uniswap v4's hook architecture gives external code a native, well-defined point to run inside a pool's own swap lifecycle. That's exactly the integration surface MEV internalization needs — and it's where Homelander is heading next, backed by a Uniswap Foundation grant.

MEV-X Team Apr 22, 2026 5 min read
Answer first

Homelander is expanding onto Uniswap v4, supported by a Uniswap Foundation grant. The integration uses v4's afterSwap hook: it fires inside the same transaction as the originating swap, so the internal MEV backrun executes atomically and the captured value flows back to the pool as yield.

Why v4's hooks matter for internalization

Uniswap v4 introduced hooks: contracts that plug into specific points in a pool's lifecycle — before and after initialization, before and after a swap, before and after liquidity changes — and run custom logic exactly there, with the pool's own execution guarantees. Before hooks existed, adding logic like MEV internalization to a Uniswap pool meant working around the core contracts rather than through a sanctioned extension point. Hooks make that unnecessary.

The afterSwap hook as the capture point

Homelander's v4 integration runs through the afterSwap hook specifically. It fires immediately after a swap executes, inside the same transaction — which means the internal backrun it triggers inherits full atomicity with the swap that created the arbitrage opportunity in the first place. There's no separate transaction, no dependency on external searcher infrastructure, and no window between the swap and the capture step for anyone else to act on the opportunity. The value flows back to the protocol as part of the same state transition the user's trade already produced.

Uniswap Foundation grant support

The expansion is backed by a grant from the Uniswap Foundation, reflecting a broader pattern: as MEV internalization becomes a more established piece of DEX infrastructure, the ecosystems most exposed to leakage have an incentive to support tooling that keeps value inside their own pools rather than routing it to external searchers by default.

  • Integration point: Uniswap v4's afterSwap hook, fired inside the same transaction as the swap.
  • Support: Uniswap Foundation grant for the v4 expansion work.
  • Guarantee preserved: internal MEV capture remains atomic with the user's swap, matching Homelander's existing execution model on other AMMs.

This expansion followed an independent security audit of the v4 hook implementation, covered separately, confirming the same isolation property that governs every Homelander integration: a failure in the internal capture path can't propagate into the user's trade.
