Homelander Security Audit: Summary and Outcomes

Bailsec's first independent audit of Homelander examined the internal MEV capture path for exactly the failure mode that matters most: what happens to the user's swap if internalization itself goes wrong.

MEV-X Team Jan 12, 2026 4 min read
Answer first

Bailsec's audit of Homelander found no exploitable vulnerabilities. Its central finding: unsuccessful internal MEV execution paths are isolated from the user's swap flow and cannot alter the swap outcome — internalization can fail safely without the user ever being exposed to that failure.

Why the isolation property was the thing to test

Any system that adds logic to an AMM's execution path introduces a question auditors have to answer directly: what happens when that added logic doesn't behave as expected? For Homelander specifically, the added logic is the internal MEV capture step — the atomic backrun that resolves the arbitrage a swap creates. Bailsec's audit focused on whether a failure in that step could ever propagate back into the user's own trade.

What the audit covered

The scope covered Homelander's core execution logic as deployed at the time: the hook/plugin integration points into the AMM, the internal accounting for captured value, and the failure paths for cases where the internal arbitrage opportunity can't be resolved cleanly — for example, when a competing state change makes the anticipated capture no longer valid by the time it executes.

The finding

Bailsec found no vulnerabilities and no high-severity issues in scope. The specific outcome worth stating plainly: unsuccessful internal MEV-related execution paths are isolated from the user swap flow and do not alter the swap outcome. In practice, that means if Homelander's internal capture step can't complete — for whatever reason, on a given block — the user's swap still executes exactly as it would have without Homelander involved. The internalization layer can fail on its own terms without failing the trade it's attached to.

  • Audit firm: Bailsec, an independent smart-contract security auditor.
  • Scope: Homelander's core internal MEV capture logic and its integration into the AMM's swap execution path.
  • Result: no exploitable vulnerabilities identified.
  • Key property confirmed: a failed internal capture path cannot alter or block the user's underlying swap.

This is the first in a series of independent audits MEV-X has commissioned as Homelander has expanded to new AMM architectures — each one re-testing the same isolation property against a new integration surface.
