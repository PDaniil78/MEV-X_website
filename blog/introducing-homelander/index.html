Introducing Homelander: Atomic MEV Internalization System

Every swap that moves an AMM pool off the wider market price creates an arbitrage opportunity. Homelander is MEV-X's system for capturing that opportunity atomically — before it ever reaches an external searcher — and returning it as yield.

MEV-X Team Dec 1, 2025 5 min read
Answer first

Homelander is MEV-X's MEV internalization system for AMMs. It captures the post-swap arbitrage opportunity atomically, in the same transaction as the swap that creates it, and returns the captured value as AMM yield instead of letting it leak to external searchers, validators, and block builders.

Every swap creates an arbitrage opportunity

A swap on a constant-product or concentrated-liquidity AMM moves the pool's internal price. If the pool was priced in line with the wider market before the trade, it usually isn't afterward — the trade itself opens a small gap between the pool's price and the price available elsewhere. That gap is an arbitrage opportunity, and on any liquid chain it gets closed within one or two blocks.

Under the default setup, closing that gap is somebody else's job. External searchers monitor the mempool, detect the imbalance, and race to backrun it — paying most of what they capture to validators and block builders as priority fees just to win the race. The pool and its liquidity providers see none of it. This is the leakage side of MEV: value created by the pool's own activity, captured entirely outside it.

What Homelander does differently

Homelander resolves that same imbalance atomically, inside the transaction that creates it, rather than leaving it for an external auction to settle later. The mechanism is triggered directly by the swap's execution path — as a plugin on the AMM itself — so the backrun that closes the arbitrage gap is not a separate transaction competing in public mempool infrastructure. It is bundled with the state transition that created the opportunity in the first place.

That has two consequences. First, the value captured no longer depends on which searcher happened to win a given block's race — it's resolved deterministically as part of the swap. Second, because it never leaves the transaction boundary, there is no window in which an external party can see the opportunity and act on it before the protocol does.

Why atomicity is the part that matters for MEV protection

Atomicity is not a performance detail — it's the property that makes internalization safe to ship. If capture happened in a follow-up transaction, it would inherit every failure mode of an external backrun: it could be front-run, it could fail to land, and a failure would need its own error handling separate from the user's original swap. Because Homelander's capture logic executes inside the same transaction, it either commits together with the swap or not at all. There's no partial state where the swap succeeds but the internalization step is left dangling, and no separate execution path a user's transaction can get stuck behind.

  • Homelander runs as an execution-layer plugin on the AMM, not a separate bot or off-chain service.
  • The user's swap price and execution are unaffected — internalization acts on the arbitrage surplus the swap creates, not on the swap itself.
  • Captured value is returned as AMM yield, on top of standard swap fees, to the pool and its liquidity providers.
  • Because capture is atomic, it carries the same execution guarantees as the swap it's attached to.

This is the starting point for MEV-X's product line: Homelander is the internalization layer, and everything else — CEX–DEX arbitrage through Starlight, liquidations through Butcher, rebated order flow through MEV-X RPC — extends the same idea to other points in the transaction lifecycle where value would otherwise leak.

What is MEV internalization?

MEV internalization is when the protocol whose activity creates an arbitrage opportunity captures that opportunity itself, instead of letting it be extracted by an external searcher and paid away as priority fees to validators and block builders.

Does Homelander change the price a user gets on their swap?

No. The arbitrage capture happens atomically around the user's swap, in the same transaction, without altering the price or execution the user sees. The value captured is the surplus that would otherwise have leaked to an external searcher.
