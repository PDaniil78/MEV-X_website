Homelander Security Audit: Uniswap v4 — Summary and Outcomes

Ahead of going live on Uniswap v4, Homelander's hook implementation went through an independent audit by MixBytes — testing whether the same isolation guarantee holds on a fundamentally different integration surface than Homelander's earlier deployments.

MEV-X Team May 6, 2026 4 min read
Answer first

MixBytes audited Homelander's Uniswap v4 hook implementation and found no critical or high-severity vulnerabilities. The audit confirmed that failures in the external execution stack are absorbed within the hook and do not propagate into the user's transaction — the same core safety property Homelander maintains across every AMM it integrates with.

A new integration surface, the same question

Uniswap v4's hook architecture is a different integration model than the plugin-based approach Homelander uses on other AMMs — hooks run with their own permissioning and lifecycle, tied directly into the pool's core swap logic. A new integration surface means the isolation property that protects users has to be re-verified from scratch, not assumed to carry over automatically from a previous audit on a different architecture. That's what this engagement tested.

Scope and findings

MixBytes reviewed the afterSwap hook implementation that Homelander uses to trigger its internal MEV capture logic on Uniswap v4 pools, along with the surrounding accounting and failure-handling paths. The audit found no critical or high-severity vulnerabilities in scope.

The specific outcome worth stating: failures in the external execution stack are absorbed within the hook and do not propagate into the user's transaction. In practice, that means if some part of the internal capture logic depends on external state or execution that doesn't resolve as expected, the hook contains that failure — it doesn't let it cascade back into the swap the user actually submitted.

  • Audit firm: MixBytes, an independent smart-contract security auditor.
  • Scope: Homelander's afterSwap hook implementation on Uniswap v4 and its internal accounting/failure paths.
  • Result: no critical or high-severity vulnerabilities identified.
  • Key property confirmed: failures in external execution are absorbed by the hook and never reach the user's swap.

This audit cleared the way for Homelander's Uniswap v4 expansion, announced separately, which runs on Uniswap Foundation grant support.
